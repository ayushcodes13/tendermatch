# Tender PDF text extraction

P4.2 reads native text from downloaded PDFs using pypdf. It never invokes OCR. Image-only documents return `needs_ocr`; encrypted files return `needs_review`; invalid files return `invalid`; inaccessible files and page parsing failures are recorded with coarse error types. Documents larger than 20 MiB are rejected before parsing. Extraction is limited to the first 100 pages and 100,000 characters per page, with pypdf's indirect-object recovery bounded. Results include at most 500 evidence values, and each quoted line is capped at 10,000 characters; oversized lines are omitted with an explicit `text_truncated` status.

The current deterministic extractor only emits fields explicitly labeled in the document: equipment type, technical specifications, mandatory and optional requirements, quantity, delivery requirements, eligibility requirements, and closing date. It does not infer an unlabeled value, resolve conflicting requirements, determine legal eligibility, or treat document text as instructions. Every emitted value carries the exact extracted line, one-based page number, and original source URL. Unlabeled prose remains available only in the original source document and is not represented as a verified requirement.

Each extraction attempt is appended to `document_extractions` with the document content fingerprint, source URL, status, evidence JSON, and timestamp. Old extraction records remain available when a PDF changes. CI uses synthetic PDFs created in tests; no live tender documents were downloaded. Native text extraction and line-label rules need evaluation against permitted, representative tender PDFs before the output is treated as operationally complete. Scanned pages remain unsupported until a separate OCR workflow is justified and tested.

PDF parsing runs in a short-lived subprocess worker with a 15-second CPU limit and a 20-second parent wall-clock timeout. The worker receives only runtime and locale environment values, so SMTP credentials are not inherited. On Linux, it also receives a 512 MiB address-space limit. On macOS, address-space limits are not applied because Python and loaded libraries may reserve virtual address space beyond that cap; CPU and wall-clock limits still apply. Platforms without POSIX resource-limit support record the extraction as unavailable rather than parsing in-process. These limits reduce impact but are not a complete sandbox: only process trusted, public documents from reviewed hosts, and retain operating-system/container isolation for production deployments.
